# V3.0 Apifox 验收指南

> 本文档只组织 Apifox 环境与按顺序执行的 V3.0 验收流程。单个接口的字段、枚举、约束和响应以导入后的 OpenAPI 契约为准。

## 1. 导入与环境

Apifox 离线导入文件：

```text
backend/v2.0/docs/openapi-v3.0-apifox.json
```

后端已启动时也可从以下 URL 导入：

```text
http://127.0.0.1:8000/openapi.json
```

新建“本地 FastAPI”环境，前置 URL 设为 `http://127.0.0.1:8000`。添加以下环境变量，密码只填写本地值，不同步到团队共享环境。

| 变量 | 初始值 | 用途 |
| ---- | ---- | ---- |
| `department_id` | 空 | 登录部门 ID |
| `shared_password` | 本地统一密码 | 仅登录请求使用 |
| `csrf_token` | 空 | 所有写请求的 `X-CSRF-Token` |
| `current_user_id` | 空 | 项目成员、负责人和版本参与人 |
| `project_id` | 空 | 当前验收项目 |
| `version_id` | 空 | 当前验收版本 |
| `task_id` | 空 | 当前验收任务 |

Apifox 需启用 Cookie 管理；“统一密码登录”响应中的 `team_session` 是 HttpOnly Cookie，不需要也不应复制到环境变量。

## 2. 登录与 CSRF 准备

### 用例 1：`auth → 【V3.0】 查询登录部门`

请求地址：`GET /api/v1/auth/departments`

从响应 `$.data` 中找到管理员所属部门，把其 `id` 保存为 `department_id`。

### 用例 2：`auth → 【V3.0】 统一密码登录`

请求地址：`POST /api/v1/auth/sessions`

```json
{
  "department_id": "{{department_id}}",
  "name": "本地验收管理员",
  "shared_password": "{{shared_password}}"
}
```

确认 HTTP 200，Apifox Cookie 管理中已保存 `team_session`。

### 用例 3：`auth → 【V3.0】 查询当前用户`

请求地址：`GET /api/v1/auth/me`

在“后置操作 → 自定义脚本”中保存 CSRF 和用户 ID：

```javascript
const body = pm.response.json();

if (body && body.code === "OK" && body.data && body.data.user && body.data.csrf_token) {
  pm.environment.set("current_user_id", body.data.user.id);
  pm.environment.set("csrf_token", body.data.csrf_token);
}
```

后续每个 `POST`、`PUT`、`PATCH`、`DELETE` 请求都增加 Header：

```text
X-CSRF-Token: {{csrf_token}}
```

## 3. 任务与版本主流程

| 顺序 | Apifox 接口 | 核心检查 |
| ---- | ---- | ---- |
| 4 | `projects → 【V3.0】 创建项目` | 创建人成为首位成员，保存 `$.data.id` 为 `project_id` |
| 5 | `projects → 【V3.0】 查询项目成员` | 返回项目统一成员顺序和 `member_revision` |
| 6 | `versions → 【V3.0】 创建版本` | `participant_ids` 使用 `current_user_id`，保存 `$.data.id` 为 `version_id` |
| 7 | `tasks → 【V3.0】 创建任务` | 负责人为 `current_user_id`，关联 `version_id`，保存 `$.data.id` 为 `task_id` |
| 8 | `tasks → 【V3.0】 查询项目任务` | `status=ALL`，返回新任务与负责人泳道修订号 |
| 9 | `versions → 【V3.0】 查询版本详情` | 版本参与人与任务负责人一致 |
| 10 | `versions → 【V3.0】 查询版本完成影响` | 核对全部任务数和未完成数 |
| 11 | `versions → 【V3.0】 更新版本` | 传入 `expected_revision`，切换完成后任务状态不变 |
| 12 | `versions → 【V3.0】 删除版本` | 返回 `unlinked_task_count`，任务仍存在且 `version_id=null` |
| 13 | `tasks → 【V3.0】 永久删除任务` | 传入任务当前 `revision`，删除后详情返回 404 |

“创建项目”可直接使用：

```json
{
  "name": "Apifox V3.0 验收项目",
  "project_context": "用于验证项目成员、团队任务与版本排期",
  "member_ids": ["{{current_user_id}}"]
}
```

“创建版本”可直接使用：

```json
{
  "name": "V3.0-Apifox",
  "start_date": "2026-08-24",
  "end_date": "2026-09-30",
  "participant_ids": ["{{current_user_id}}"]
}
```

“创建任务”可直接使用：

```json
{
  "name": "Apifox 共用任务",
  "assignee_id": "{{current_user_id}}",
  "status": "NOT_STARTED",
  "priority": "P1",
  "version_id": "{{version_id}}",
  "start_date": "2026-08-24",
  "due_date": "2026-08-28",
  "description": "同时出现在团队任务和版本排期"
}
```

## 4. 异常与安全检查

- 不携带 Cookie 请求任意业务接口，预期 HTTP 401。
- 携带 Cookie 但删除 `X-CSRF-Token` 执行写请求，预期 HTTP 403。
- 使用旧 `expected_revision` 重复更新任务或版本，预期 HTTP 409。
- 将项目归档后查询仍成功，任务、版本、排序等写请求失败。
- Apifox 请求中不填写 Dify API Key；所有 Workflow Key 只保存在后端 `.env`。
