# V3.0 本地验收启动指南

## 1. 验收前检查

- `backend/v2.0/.env` 已填写本地统一密码、会话密钥、邀请码加密密钥和 Dify 配置；
- `DATABASE_URL` 明确指向本次验收库，不对未确认的数据库执行清空操作；
- 首个管理员初始化命令只在系统尚无管理员时执行一次。

## 2. 启动后端

在终端 1 执行：

```bash
cd backend/v2.0
source .venv/bin/activate
python -m alembic upgrade head
python -m app.db.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

如果是全新空库且系统中尚无管理员，在启动 Uvicorn 前额外执行：

```bash
python scripts/bootstrap_admin.py --department 产品部 --name 本地验收管理员
```

后端验证地址：

```text
http://127.0.0.1:8000/api/v1/health
http://127.0.0.1:8000/api/v1/ready
http://127.0.0.1:8000/docs
http://127.0.0.1:8000/openapi.json
```

`health` 只表示进程存活；`ready` 同时校验数据库可连接且 Alembic 已到 head。

## 3. 启动前端

在终端 2 执行：

```bash
cd frontend/v2.0
pnpm install --frozen-lockfile
pnpm run generate:api
pnpm run dev
```

浏览器访问：

```text
http://127.0.0.1:3000
```

## 4. Apifox

优先导入：

```text
backend/v2.0/docs/openapi-v3.0-apifox.json
```

或在后端运行时从 `http://127.0.0.1:8000/openapi.json` 导入。登录 Cookie、CSRF Header 和测试变量的配置见 [V3.0 Apifox 验收指南](./V3.0-Apifox验收指南.md)。

## 5. 建议验收顺序

1. `health` 和 `ready` 均返回 HTTP 200；
2. 管理员使用部门、姓名和统一密码登录；
3. 创建项目并选择首批成员；
4. 在团队任务中创建任务，验证面板和甘特图；
5. 创建版本、选择参与人，验证排期列表和甘特图；
6. 从任一模块编辑同一任务，确认另一模块同步更新；
7. 完成/重开版本、删除版本并确认任务不丢失；
8. 归档项目，确认可查看但所有写操作禁用。
