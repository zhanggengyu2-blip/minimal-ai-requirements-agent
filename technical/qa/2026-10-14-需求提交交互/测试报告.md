# 需求提交与看板交互测试报告

日期：2026-10-14（Asia/Shanghai）

后续进展：用户已批准在当前版本增加可选 AI 分析，并修复 F01、F02、移除 F03 的前端入口。修复与回归已完成，详见 [修复与回归记录](../2026-10-14-AI开关与缺陷修复/修复与回归记录.md)。以下保留本轮修复前的原始测试结果。

## 结论

本轮实际执行 23 个检查项：16 项通过，7 项未通过。未通过项归属于 3 个问题，其中 AI 失败后的反馈缺失会诱导重复提交，项目页面初次进入或刷新会显示错误的数据范围。当前流程尚不满足完整交互验收。

本轮只进行测试、生成隔离测试数据和记录证据，没有修改应用业务代码。下一版本的留言与文档开发按用户要求搁置；这些功能此前确认的规则继续保留。

## 测试依据与环境

- 依据现有产品约定、运行说明，以及本聊天确认的行为：Dify 不可用时仍保存原始需求，并明确告知 AI 分析失败。
- 项目页面应展示对应项目的需求；提交成功后的列表和数量应更新；归档项目保持只读。
- 使用独立 SQLite 测试库和测试管理员，前端 `localhost:3001`，后端 `127.0.0.1:8001`。原应用的 `127.0.0.1:3000` 和 `8000` 不用于生成本轮测试数据。
- 成功、HTTP 503、超时及非法结果由本机模拟服务提供；连接失败通过停止模拟服务进程验证。成功分支仅验证应用处理有效分析结果的行为，不代表真实 Dify Workflow 或模型质量已通过测试。
- 临时前端使用独立缓存和 API 转发，排除并行开发服务器的缓存与跨域干扰；没有改动项目的正式配置。
- 本轮主要使用实际浏览器操作，再核对后端响应与数据库；并非只依据路由可调用来判断通过。

## F01 · P1：AI 失败后，已经保存的需求没有页面反馈

复现：打开 A 的提交需求弹窗，填写带有“连接失败”的测试内容并提交；模拟 AI 返回 HTTP 503。后端保存需求并以 HTTP 201 返回 `AI_ANALYSIS_FAILED`。

预期：明确提示“需求已保存，AI 分析失败”，关闭提交弹窗并更新看板和数量，使用户知道保存已经完成。

实际：弹窗保持原状，看板和侧栏数量不变；错误只出现在浏览器日志。再次点击同一按钮会新增另一条需求。离线、超时和非法分析结果均有相同问题。

代码定位：`frontend/src/api/http.ts:73` 的响应处理拒绝所有非 `OK` 业务码；`frontend/src/components/RequirementDialog.vue:45` 原本用于处理 `FAILED` 的反馈逻辑因此无法执行，且提交函数没有处理这次拒绝的提示。

建议后续修复：区分“需求已保存但分析失败”和“保存本身失败”，让前者走保存完成的反馈与刷新路径。这里的重复记录是这次误导交互的结果，并不据此新增“所有相同内容永远不得重复提交”的业务规则。

证据：[失败弹窗截图](01-AI失败后弹窗未关闭.png)、[超时页面状态](02-AI超时后页面状态.txt)、[服务离线页面状态](07-AI服务离线后页面状态.txt)、[实际保存结果](接口与保存结果.json)。

## F02 · P1：项目需求页面首次挂载或刷新时丢失项目筛选

复现：准备 A 和 B 两个项目，在 B 创建“QA-B专属”需求；打开 A 的需求页并刷新。

预期：主区只展示 A 的需求，标题显示 A，数量与 A 一致。

实际：侧栏选中 A，URL 为 `/projects/c10a7c9adee74090a2bc2bd15644c449/requirements`，主区却显示“全部项目”和 B 的专属需求。证据截图阶段 A 有 6 条、B 有 1 条，主区显示 7 条。通过侧栏从 B 切回 A 后恢复正常。

代码定位：`frontend/src/views/RequirementBoard.vue:98` 的项目监听没有初始化执行；`query.project_id` 初始为空，`onMounted(load)` 因而查询全部可见项目。

建议后续修复：首次查询前初始化项目筛选，并覆盖直接打开 URL、刷新以及侧栏切换的回归场景。本次使用管理员且两个项目均可访问；发现的是显示范围错误，未据此认定存在越权访问。

证据：[刷新后截图](04-项目A刷新混入项目B.png)、[URL 与页面上下文](04-项目A刷新上下文.json)。

## F03 · P2：批量分析按钮没有说明功能尚为预留

复现：在有需求的看板点击“AI批量分析”。

实际：后端返回 HTTP 202、`ACCEPTED`，数据中的状态为 `RESERVED`，说明异步任务尚未实现；需求状态不变。前端把该业务码当作异常，页面没有任何说明。

代码定位：`backend/app/api/routes/requirements.py:117`、`backend/app/schemas/requirement.py:66` 明确为预留功能；前端 `RequirementBoard.vue` 显示可点击入口，与通用响应处理不匹配。

建议后续处理：在功能实现前禁用入口或明确说明尚不可用，避免让用户以为已经提交了分析任务。真正执行批量分析的功能开发仍需另行确定，不纳入这次测试。

证据：[浏览器错误日志](06-批量分析错误日志.json)、[接口返回及需求状态](接口与保存结果.json)。
