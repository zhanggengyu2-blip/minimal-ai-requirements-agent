# V3.0 数据库初始化与迁移方案

> 对应决定：Q5 A、Q6 技术推荐 A、Q7 C
> 结论：一次性清空测试库，但仍从 V3.0 开始使用 Alembic

## 1. 为什么清空测试数据后仍需要 Alembic

清空数据库解决的是“旧测试数据要不要保留”；Alembic 解决的是“数据库结构以后如何可靠变化”。两者不是同一个问题。

当前 `Base.metadata.create_all()` 只能补建不存在的表，不会可靠地删除字段、修改约束、调整索引或记录已执行版本；现有手写 `ALTER TABLE` 也会随着版本增加变得不可审查。即使 V3.0 从空库开始，V3.1 增加字段时仍需要明确的升级路径。因此：

- V2 测试数据不迁移；
- V3.0 创建第一条完整 Alembic 基线；
- V3.0 之后每次结构变化都新增迁移文件。

## 2. V3.0 一次性重建流程

正式实施时按以下顺序执行：

1. 停止后端，确认没有进程持有 SQLite 文件；
2. 解析配置得到数据库绝对路径，并确认目标严格位于 `backend/v2.0/data/`；
3. 明确列出主库、`-wal`、`-shm` 三个目标；
4. 因用户已确认均为测试数据，不制作业务数据迁移和回填脚本；
5. 删除经过校验的数据库文件；
6. 执行 `alembic upgrade head` 创建 V3.0 完整结构；
7. 运行首个管理员初始化命令；
8. 启动服务并运行冒烟测试。

清空动作不放在应用启动流程中，也不由迁移脚本自动删除未知数据库。它应是一次显式、可核对目标的开发操作。

## 3. Alembic 目录和职责

建议结构：

```text
backend/v2.0/
├── alembic.ini
├── migrations/
│   ├── env.py
│   └── versions/
│       └── 0001_v3_baseline.py
└── app/
```

- `0001_v3_baseline.py`：一次性创建现有 V2 业务表和 V3 新表的最终结构；
- 应用启动不再执行生产结构迁移；
- `init_db()` 只保留测试辅助能力或删除，正式环境统一先运行 `alembic upgrade head`；
- 默认部门种子数据通过独立、幂等的 seed 命令写入，不混进结构迁移。

## 4. SQLite 运行配置

每个连接启用：

```text
PRAGMA foreign_keys = ON
PRAGMA busy_timeout = 5000
```

数据库初始化后启用：

```text
PRAGMA journal_mode = WAL
PRAGMA synchronous = NORMAL
```

部署约束：

- 单服务器；
- 单个后端实例；
- 小团队、低并发写入；
- 数据库文件位于本地可靠磁盘，不放在网络共享盘；
- 当前阶段暂不建立自动备份；该风险由第三轮 QA 明确接受。

如果未来需要多实例、高并发写入或公网大规模使用，应迁移 PostgreSQL，不继续堆叠 SQLite 补丁。

## 5. 后续升级流程

每次模型变化必须：

1. 新建一条 Alembic revision；
2. 人工审查升级和降级内容，不能直接信任自动生成；
3. 在空库执行 `upgrade head`；
4. 在上一版本样本库执行升级；
5. 运行外键检查、模型测试和 API 回归；
6. 在尚未建立备份策略前，只允许对可重新生成的测试数据执行结构升级；
7. 正式数据开始积累后，在下一次结构升级前必须先补充备份与恢复方案。

SQLite 对部分 `ALTER TABLE` 支持有限，复杂字段或约束变化使用 Alembic batch mode 重建表。

## 6. 当前备份决定与已接受风险

第三轮 QA 选择暂不建立备份策略，原因是项目尚未正式使用。当前 V3.0 范围因此不包含：

- 自动备份任务；
- 备份保留周期；
- 异地或独立磁盘存储；
- 自动恢复和恢复演练；
- 单条任务恢复。

系统正式上线后再单独制定备份策略。在该策略落地前，数据库损坏、磁盘故障、误删除或迁移失败都可能造成无法恢复的数据丢失；永久删除任务同样无法恢复。该风险已由用户明确接受。

## 7. 验收检查

- 全新空目录执行 `alembic upgrade head` 后所有表、索引、外键和检查约束存在；
- 重复执行 `upgrade head` 不改变数据；
- `alembic current` 与 `head` 一致；
- 外键检查结果为空；
- WAL、外键和 busy timeout 配置生效；
- 应用不依赖 `create_all` 才能启动；
- 首个管理员命令不可重复创建管理员；
- 单元测试使用独立临时数据库，不触碰本地开发库。
