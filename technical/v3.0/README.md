## 1. 已确认的技术决定

| 项目 | 决定 |
|---|---|
| 身份体系 | 首次注册使用“部门＋姓名＋邀请码”；后续登录使用“部门＋姓名＋公司统一密码” |
| 项目成员 | 建立显式项目成员关系并提供成员管理入口 |
| 管理员 | `ADMIN` / `MEMBER` 两级角色；首个管理员由一次性初始化命令创建 |
| 部门 | 只支持新增、改名和永久删除，不提供停用/启用 |
| 数据库 | V3.0 继续使用 SQLite，限定单服务器、单后端实例、小团队低并发 |
| 数据过渡 | 当前数据库均为测试数据，V3.0 实施时一次性清空并重建 |
| 迁移工具 | 从 V3.0 开始接入 Alembic，初始迁移即为 V3.0 完整结构 |
| 并发 | 任务、版本和排序使用乐观并发控制，冲突时拒绝静默覆盖 |
| 操作审计 | 本期不建操作审计表，不保存操作历史或恢复记录 |
| 任务加载 | 搜索和筛选由后端执行，单次最多返回 1000 条，超出时提示缩小范围 |
| 前端路由 | 引入 Vue Router；模块、项目和版本使用稳定 URL |
| 共享部署 | 部署在一台长期在线的公司内网服务器或共享主机，使用统一 HTTPS 地址 |
| 运行保障 | 开机自启、异常重启、健康检查和轮转日志，不采购外部监控服务 |
| 会话 | 空闲 7 天失效，最长 30 天；有效使用时续期 |
| 项目归档 | 任意项目成员均可归档或重新打开项目 |
| 设计门禁 | 后端和非视觉基础先开发；任务与版本正式页面等待新版设计冻结 |
| 自动检查 | 使用 GitHub Actions 执行测试、构建和契约一致性检查 |
| 备份 | 当前阶段不建立备份策略，正式上线后再单独规划并接受其间不可恢复风险 |

## 3. 实施边界

- 继续使用 Vue 3、TypeScript、Element Plus、FastAPI、SQLAlchemy 和 `/api/v1`；
- 本组文档定义实现约束，不修改已冻结的团队任务与版本排期产品基线；
- 当前阶段只交付方案，不修改业务代码、不执行数据库清空；
- 数据库清空属于正式开发开始后的显式步骤，执行前仍需核对目标文件路径；
- 项目知识库、复杂权限、完整审计、恢复站、实时协同和多实例部署不属于 V3.0。

## 4. 必须遵守的一致性规则

- 一个任务只有一条记录；任务面板与版本排期只是在不同范围内读取同一条数据；
- 任务负责人必须是项目成员；版本参与人员也必须是项目成员；
- 给版本任务更换负责人时，如新负责人尚未参与版本，则在同一事务中自动加入版本参与人员；
- 删除版本只解除任务的版本关联，不删除任务；
- 项目成员仍负责任务时禁止移除；版本参与人员仍负责该版本任务时禁止移除；
- 归档项目内的任务、版本、需求和访谈写接口均拒绝执行；项目成员仍可把项目重新打开；
- 不通过“最后写入者胜出”覆盖任务、版本或排序冲突。
