# V3.0 数据模型设计

> 状态：已确认技术方案
> 数据库：SQLite
> ID：32 位无连字符 UUID 字符串
> 时间：UTC 时间戳；任务与版本业务日期使用 `DATE`

## 1. 关系总览

```text
department
├── user_account
├── invitation_code
└── project（可选所属部门）

user_account
├── auth_session
├── project_member ── project
├── task.assignee_id
└── version_participant

project
├── requirement / interview_session（现有）
├── project_member
├── task_lane ── task
└── project_version ── version_participant
                         └── task.version_id（可空）
```

任务只保存在 `task` 表。团队任务和版本排期不是两套表：版本视图只查询 `task.version_id` 等于当前版本的数据。

## 2. 身份与组织表

### 2.1 `department`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `name` | `VARCHAR(100)` | 非空、唯一 |
| `created_time` | `DATETIME` | 非空 |
| `updated_time` | `DATETIME` | 非空 |

V3.0 删除现有 `status` 字段，不再保留 `ACTIVE/DISABLED` 状态。

### 2.2 `invitation_code`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `code_digest` | `VARCHAR(64)` | 非空、唯一，用于核销查询 |
| `code_ciphertext` | `TEXT` | 非空，独立密钥加密，用于管理员列表查看和复制 |
| `department_id` | `VARCHAR(32)` | 外键，删除限制 |
| `intended_user_name` | `VARCHAR(50)` | 可空 |
| `status` | `VARCHAR(16)` | `UNUSED/USED/DISABLED` |
| `used_by_user_id` | `VARCHAR(32)` | 可空、唯一外键 |
| `created_by` | `VARCHAR(32)` | 管理员用户外键；仅首个管理员引导记录可空 |
| `created_time` | `DATETIME` | 非空 |
| `used_time` | `DATETIME` | 可空 |
| `disabled_time` | `DATETIME` | 可空 |

### 2.3 `user_account`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `department_id` | `VARCHAR(32)` | 非空外键，删除限制 |
| `name` | `VARCHAR(50)` | 非空 |
| `normalized_name` | `VARCHAR(50)` | 非空，登录比较使用 |
| `role` | `VARCHAR(16)` | `ADMIN/MEMBER` |
| `invitation_id` | `VARCHAR(32)` | 可空、唯一外键；首个管理员为空 |
| `created_time` | `DATETIME` | 非空 |
| `updated_time` | `DATETIME` | 非空 |

建立 `(department_id, normalized_name)` 唯一约束。同一部门内不允许同名注册，不同部门允许同名；日常登录使用部门、规范化姓名和公司统一密码定位用户。

公司统一密码不属于用户数据，不在数据库建立密码字段；由部署环境变量提供。

### 2.4 `auth_session`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `user_id` | `VARCHAR(32)` | 非空外键，级联删除 |
| `token_digest` | `VARCHAR(64)` | 非空、唯一 |
| `idle_expires_time` | `DATETIME` | 非空、索引，最后活动后 7 天 |
| `absolute_expires_time` | `DATETIME` | 非空、索引，创建后最长 30 天 |
| `last_seen_time` | `DATETIME` | 非空 |
| `revoked_time` | `DATETIME` | 可空 |
| `created_time` | `DATETIME` | 非空 |

## 3. 项目成员

### 3.1 `project` 调整

保留现有项目字段，并做以下约束调整：

- `department_id` 改为真实外键，部门删除时限制；
- `created_by` 改为用户外键；
- 项目创建后必须在同一事务中写入创建者的 `project_member`；
- `status` 继续使用 `ACTIVE/ARCHIVED`；
- 增加 `revision` 保护项目基础信息，增加 `member_revision` 保护项目成员集合；
- 归档状态由所有写服务统一校验，而不是只靠前端禁用。

### 3.2 `project_member`

| 字段 | 类型 | 约束 |
|---|---|---|
| `project_id` | `VARCHAR(32)` | 联合主键、项目外键，级联删除 |
| `user_id` | `VARCHAR(32)` | 联合主键、用户外键，删除限制 |
| `added_by` | `VARCHAR(32)` | 操作者用户外键 |
| `created_time` | `DATETIME` | 非空 |

索引：`(user_id, project_id)`，支持普通用户项目列表。

## 4. 任务与排序

### 4.1 枚举

- `TaskStatus`：`NOT_STARTED`、`IN_PROGRESS`、`COMPLETED`、`CANCELED`；
- `TaskPriority`：`P0`、`P1`、`P2`、`P3`。

“未完成”不是数据库状态，查询时展开为 `NOT_STARTED + IN_PROGRESS`。

### 4.2 `task`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `project_id` | `VARCHAR(32)` | 非空外键，级联删除 |
| `assignee_id` | `VARCHAR(32)` | 非空用户外键，删除限制 |
| `version_id` | `VARCHAR(32)` | 可空版本外键，删除时置空 |
| `name` | `VARCHAR(200)` | 非空 |
| `description` | `TEXT` | 非空、默认空串，最多 500 字符由服务校验 |
| `status` | `VARCHAR(20)` | 非空，默认 `NOT_STARTED` |
| `priority` | `VARCHAR(2)` | 非空，默认 `P1` |
| `start_date` | `DATE` | 可空 |
| `due_date` | `DATE` | 可空 |
| `sort_order` | `INTEGER` | 非空，同一泳道内稳定排序 |
| `revision` | `INTEGER` | 非空，默认 1，乐观锁 |
| `created_by` | `VARCHAR(32)` | 非空用户外键 |
| `updated_by` | `VARCHAR(32)` | 非空用户外键 |
| `created_time` | `DATETIME` | 非空 |
| `updated_time` | `DATETIME` | 非空 |

约束和索引：

- `due_date IS NULL OR start_date IS NULL OR due_date >= start_date`；
- `version_id` 非空时，版本必须属于同一个项目；该规则由服务事务校验；
- `(project_id, assignee_id)` 使用组合外键指向 `project_member`，从数据库层保证负责人属于项目；
- 索引 `(project_id, assignee_id, sort_order)`；
- 索引 `(project_id, status, sort_order)`；
- 索引 `(version_id, assignee_id, sort_order)`；
- 名称搜索使用 SQLite `LIKE`；达到性能瓶颈后再评估 FTS，不在 V3.0 提前引入。

### 4.3 `task_lane`

用于保护同一项目、同一负责人的排序并发：

| 字段 | 类型 | 约束 |
|---|---|---|
| `project_id` | `VARCHAR(32)` | 联合主键、项目外键 |
| `assignee_id` | `VARCHAR(32)` | 联合主键、用户外键 |
| `revision` | `INTEGER` | 非空，默认 1 |
| `updated_time` | `DATETIME` | 非空 |

新建任务、修改负责人和拖拽排序均在事务中更新对应泳道。排序请求携带 `task_lane.revision`；不一致时返回 409，前端刷新完整泳道后再操作。

## 5. 版本

### 5.1 `project_version`

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `VARCHAR(32)` | 主键 |
| `project_id` | `VARCHAR(32)` | 非空外键，级联删除 |
| `name` | `VARCHAR(100)` | 非空，同项目唯一 |
| `start_date` | `DATE` | 非空 |
| `end_date` | `DATE` | 非空且不早于开始日期 |
| `status` | `VARCHAR(16)` | `NOT_STARTED/IN_PROGRESS/COMPLETED` |
| `revision` | `INTEGER` | 非空，默认 1 |
| `created_by` | `VARCHAR(32)` | 非空用户外键 |
| `updated_by` | `VARCHAR(32)` | 非空用户外键 |
| `created_time` | `DATETIME` | 非空、排序索引 |
| `updated_time` | `DATETIME` | 非空 |

不同版本允许日期重叠。版本名同项目唯一是为避免切换下拉出现无法区分的同名项。

### 5.2 `version_participant`

| 字段 | 类型 | 约束 |
|---|---|---|
| `version_id` | `VARCHAR(32)` | 联合主键、版本外键，级联删除 |
| `user_id` | `VARCHAR(32)` | 联合主键、用户外键，删除限制 |
| `created_time` | `DATETIME` | 非空 |

参与人员必须同时是版本所属项目的项目成员。版本至少一名参与人员；移除最后一人或移除仍负责该版本任务的人时由服务拒绝。

## 6. 现有表调整

当前测试库会清空，因此无需编写旧数据回填逻辑。新基线中：

- `requirement.created_by`、`interview_session.created_by`、`interview_attachment.uploaded_by` 在业务允许为空时改为用户外键；
- 新建记录统一从当前会话读取操作者，不再相信客户端提交的 `created_by`；
- 保留需求、访谈及附件现有业务表，但用初始迁移一次性创建最终结构；
- 不创建 `audit_log`、任务历史、回收站或软删除字段。

## 7. 事务边界

以下动作必须单事务完成：

- 首次邀请码注册：用户、邀请码和会话；
- 日常统一密码登录：用户校验和会话；
- 创建项目：项目和首位项目成员；
- 创建或修改任务：任务、泳道顺序和自动加入版本参与人员；
- 修改任务负责人：旧泳道、新泳道和任务修订号；
- 删除版本：任务解除关联和版本删除；
- 修改版本参与人员：成员校验、参与关系和版本修订号；
- 批量排序：完整泳道顺序和泳道修订号。
