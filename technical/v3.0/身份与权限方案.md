# V3.0 身份与权限方案

> 状态：已确认技术方案
> 对应决定：第二轮 Q1 A、Q2 A、Q3 A、Q4 用户修订、Q9 B；第三轮 Q4-1 B、Q4-2 B、Q5 A

## 1. 目标

为现有系统补齐可识别当前操作者的轻量身份体系，并让项目成员、任务负责人、版本参与人员和管理员权限有可靠的数据来源。本期不引入手机号、邮箱、个人密码、第三方登录或复杂角色模型。首次注册使用邀请码，日常登录使用公司统一密码。

## 2. 身份模型

### 2.1 角色

- `ADMIN`：管理部门、邀请码，并可查看全部项目和协助维护所有项目的成员；
- `MEMBER`：只能访问自己参与的项目。

角色只解决系统级管理权限。任务与版本仍遵循产品基线：项目成员共同维护，不增加任务创建人、版本创建人或负责人专属编辑权限。

### 2.2 首次注册

首次注册提交部门、姓名和邀请码：

1. 邀请码必须为 `UNUSED`，并与预设部门、可选预设姓名一致；
2. 同一部门内不得已存在同名用户；
3. 校验通过后，原子地创建用户、绑定邀请码、将邀请码改为 `USED` 并建立会话；
4. 邀请码为 `USED`、`DISABLED` 或不存在时拒绝注册。

同一个邀请码只能绑定一个用户。并发提交时依靠唯一约束和事务保证不会创建两个账号。

### 2.3 日常登录与统一密码

注册后的用户使用“部门＋姓名＋公司统一密码”登录。统一密码由部署环境配置，不为每个用户单独保存密码字段。

- 同部门用户姓名唯一，不同部门允许同名；
- 后端使用常量时间比较校验统一密码；
- 统一密码不得提交到仓库、写入数据库、日志、URL 或前端持久化存储；
- 修改统一密码只影响后续登录；如需同时退出现有用户，由管理员执行撤销全部会话命令；
- 当前阶段不提供用户停用、离职处理、个人密码修改或找回密码功能；
- 已离职人员的历史记录保留，且只要仍能访问内网并知道统一密码，技术上仍可继续登录。这是第三轮明确接受的阶段性风险。

### 2.4 邀请码保存与展示

- 管理员列表持续展示并允许复制邀请码；
- 数据库保存用于精确查询的 HMAC 摘要，以及使用独立密钥加密的可恢复密文；
- 解密只允许管理员邀请码列表接口使用；
- 日志、错误详情和请求追踪信息不得记录邀请码；
- 前端邀请码输入框默认隐藏，不写入 localStorage、sessionStorage 或 URL。

邀请码仅用于首次注册，不是日常登录凭据。

### 2.5 会话

- 登录成功后创建服务端会话；
- 浏览器只保存随机会话令牌，使用 `HttpOnly`、`SameSite=Lax` Cookie；生产环境启用 `Secure`；
- 数据库存储令牌摘要，不保存原始令牌；
- 连续 7 天未使用的会话失效，单次登录最长保持 30 天；
- 有效访问时滚动更新空闲过期时间，但不得突破 30 天绝对上限；
- 用户退出时立即撤销当前会话；
- 每次鉴权检查会话未撤销、未超过空闲期限和绝对期限且用户仍存在；

## 3. 首个管理员

使用一次性初始化命令创建，不采用“第一个注册者自动成为管理员”：

```text
bootstrap-admin --department <部门名称> --name <管理员姓名>
```

命令行为：

1. 仅在不存在管理员时允许执行；
2. 创建或复用指定部门；
3. 直接创建 `ADMIN` 用户；首个管理员不要求先持有邀请码；
4. 管理员随后使用部门、姓名和公司统一密码登录；
5. 重复执行时拒绝，不静默新增第二个管理员。

本期不提供用户管理或角色调整页面。首个管理员承担部门、邀请码及跨项目成员协助工作；新增管理员属于后续范围。

## 4. 部门规则

部门只保留以下操作：

- 新增部门；
- 修改部门名称；
- 删除部门。

不再提供部门状态、停用、启用以及“停用部门用户不能登录”的逻辑。部门名称全局唯一，比较前去除首尾空格。

为了避免产生无归属用户或失效登录信息，存在以下任一引用时禁止删除部门，并返回具体引用数量：

- 用户；
- 项目；
- 邀请码，包括未使用、已使用和已停用记录。

管理员应先处理引用后再删除。V3.0 不提供级联删除用户、项目或邀请码的快捷操作。

## 5. 项目成员

### 5.1 来源和维护

- 项目成员只能从已注册内部用户中选择；
- 任意登录用户可沿用当前行为创建项目，创建者自动成为首位项目成员；
- 当前项目成员可以添加或移除其他成员；
- 任意项目成员均可归档或重新打开项目；
- 管理员可以查看全部项目并协助维护项目成员；
- 项目至少保留一名成员；
- 成员仍负责该项目任一任务时禁止移除，必须先转交任务。

### 5.2 可见范围

- 普通成员的项目列表只返回其参与的项目；
- 管理员项目列表可返回全部项目；
- 普通成员直接访问非本人项目返回 `404`，避免泄露项目存在性；
- 管理员可查看所有项目并维护成员；若要创建、编辑或删除该项目的任务和版本，管理员也必须先成为项目成员。

## 6. 权限矩阵

| 操作 | 未登录 | 普通成员 | 管理员 |
|---|---:|---:|---:|
| 获取登录页部门选项 | 允许 | 允许 | 允许 |
| 注册/登录 | 允许 | 不适用 | 不适用 |
| 查看自己的会话信息 | 禁止 | 允许 | 允许 |
| 管理部门和邀请码 | 禁止 | 禁止 | 允许 |
| 查看用户选择列表 | 禁止 | 允许 | 允许 |
| 创建项目 | 禁止 | 允许 | 允许 |
| 查看项目 | 禁止 | 仅本人项目 | 全部项目 |
| 管理项目成员 | 禁止 | 本人项目 | 全部项目 |
| 查看任务和版本 | 禁止 | 本人项目 | 全部项目只读 |
| 修改任务和版本 | 禁止 | 本人项目 | 仅已加入的项目 |
| 修改归档项目内业务数据 | 禁止 | 禁止 | 禁止 |
| 重新打开归档项目 | 禁止 | 项目成员允许 | 已加入项目时允许 |

## 7. 无审计的已接受风险

本期不记录操作者、操作类型或删除历史，也不提供恢复功能。系统仍在数据表保留 `created_by`、`updated_by` 等当前归属字段，用于展示和业务处理，但它们不构成不可篡改审计链。永久删除任务后无法回答“谁在何时删除了什么”，该风险由用户在 Q9 选择方案 B 后接受。

## 8. 验证重点

- 同一邀请码并发首次使用时只创建一个用户；
- 登录错误只返回产品已定义的无效、已使用或身份不匹配类别，不泄露绑定用户或内部字段；
- 普通成员无法通过猜测 ID 访问其他项目；
- 管理员无法绕过归档只读规则；
- 删除被引用部门、移除仍负责任务的成员均返回明确冲突错误；
- 邀请码不以数据库明文字段保存，只在管理员接口解密返回；不得出现在日志或 URL 中；
- 会话令牌不出现在数据库明文字段、响应正文、日志或 URL 中；
- 统一密码不出现在数据库、日志、响应、URL 或前端持久化存储中；
- 同部门同名注册被唯一约束拒绝；不同部门同名用户可分别登录；
- 会话分别覆盖 7 天空闲过期和 30 天绝对过期边界。
