# V3.0 前端架构方案

> 状态：开发前架构基线
> 技术栈：Vue 3、TypeScript、Element Plus、Axios、Vue Router

## 1. 改造目标

当前前端主要由单个 `App.vue` 通过内存状态切换页面。V3.0 将模块、鉴权、项目和版本状态拆开，保证：

- 刷新、后退和书签能够恢复当前模块、项目和版本；
- 搜索、筛选和甘特刻度只在当前访问期间保留，刷新后恢复产品默认值；
- 登录、管理员入口和项目可见性有统一守卫；
- 任务面板、两个甘特图和版本排期复用同一任务 API 类型；
- `App.vue` 不继续膨胀为全部业务页面的容器。

## 2. 路由

建议路由：

```text
/login
/projects
/projects/:projectId/requirements
/projects/:projectId/interviews
/projects/:projectId/tasks/board
/projects/:projectId/tasks/gantt
/projects/:projectId/versions
/projects/:projectId/versions/:versionId/list
/projects/:projectId/versions/:versionId/gantt
/admin/departments
/admin/invitations
```

规则：

- 未登录访问受保护路由时跳转 `/login`，登录后回到原目标；
- 已登录访问 `/login` 时跳转首个可见项目或项目管理；
- `/admin/*` 由角色守卫限制为管理员；
- `/versions` 查询版本列表：存在版本时替换为最新版本的 `/list`，没有版本时停留并展示空状态；
- 归档项目仍可进入任务和版本路由，但页面读取 `readOnly` 上下文禁用所有写操作；
- 项目或版本不可见时展示 404 页面，不回退到一个可能误导用户的默认项目。

登录页在同一路由中提供“登录”和“首次注册”两种模式：登录使用部门、姓名和公司统一密码；注册使用部门、姓名和邀请码。

## 4. 页面状态

### 4.1 路由状态

以下状态写入 URL：

- 当前项目；
- 当前模块；
- 列表/甘特视图；
- 当前版本。

以下状态只保存在当前页面组件或模块 composable：

- 搜索词；
- 状态筛选；
- 甘特日/周/月刻度；
- 时间轴滚动位置；
- 弹窗表单草稿。

因此同一模块内切换列表和甘特时可由父路由容器保留筛选与刻度，刷新后按产品要求恢复默认。

### 4.2 请求状态

每个页面明确区分：

- `loading`：首次加载；
- `ready`：数据可用；
- `empty`：请求成功但业务为空；
- `error`：请求失败，可重新加载；
- `submitting`：写请求中，禁用重复提交；
- `conflict`：409，需要刷新后重新编辑。

不得在首次请求完成前展示“0 条任务”或“暂无版本”。

## 5. HTTP 和鉴权

调整现有 Axios 实例：

- `withCredentials: true`；
- 从当前会话上下文附加 CSRF 请求头；
- 401：清空当前用户并跳转登录页，保存返回地址；
- 403 `PROJECT_ARCHIVED`：保持页面数据，切换为只读并提示；
- 409 修订冲突：不使用全局通用错误文案，交给页面展示“数据已被他人修改”；
- 422：继续展示字段级校验；
- 网络错误和 Dify 错误沿用现有分类逻辑；
- 所有请求继续携带 `X-Request-ID`。

邀请码和统一密码字段标记为敏感，不进入错误对象序列化、日志或埋点。统一密码不写入浏览器持久化存储。

会话连续 7 天未使用后失效，最长保持 30 天。前端收到 401 后返回登录页，不尝试使用统一密码自动登录。

## 6. 任务模块

### 6.0 项目成员来源与顺序

- 不新增系统成员管理路由；`GET /users` 只作为“新建项目”和“管理项目成员”选择器的数据源；
- `ProjectDialog` 自动固定当前用户，提交完整 `member_ids`；
- `ProjectMemberDialog` 用上移/下移维护有序 `selectedIds`，添加用户时追加末尾；
- 任务面板、两个甘特图和版本参与人员都使用服务端项目成员顺序，不在前端另存顺序。

### 6.1 数据加载

- 页面一次请求获取筛选后的全部任务、总数和泳道修订号；
- 项目成员单独加载并始终完整展示；
- 前端不预先判断成员 200 条任务上限，也不增加专门面板状态或禁用负责人选项；创建或转交返回容量冲突时保留表单并展示服务端错误；
- 搜索输入 300ms 防抖；状态变化立即请求；
- 请求返回后按成员列表组装泳道，零任务成员保留。

### 6.2 创建和编辑

- 全局新建、泳道新建、版本成员新建共用 `TaskDialog`；
- 入口上下文只负责预填 `assignee_id` 和 `version_id`；
- 提交后以后端返回对象为准更新页面，不在前端复制规则；
- 409 时保留用户表单，展示冲突提示，并提供“查看最新数据”；
- 修改负责人或版本后刷新受影响泳道和版本参与人员。

### 6.3 排序

- 只在团队任务面板且拥有完整泳道数据时启用；成员达到 200 条任务不影响已有任务排序；
- 拖拽时先保存旧顺序；成功后采用服务端新修订号；失败或冲突时恢复旧顺序并重新加载；
- 筛选状态下先读取完整泳道 ID 顺序，把可见任务的新顺序稳定合并回完整序列后提交；

## 7. 甘特图

不采购商业组件，使用 Vue 组件和 CSS Grid/绝对定位实现只读基础甘特：

- `GanttShell`：刻度、今天、左右移动、横向滚动；
- `GanttMemberGroup`：成员标题和任务行；
- `GanttTaskBar`：统一蓝色任务条和点击交互；
- `useGanttScale`：日/周/月日期单元、像素换算和窗口移动；
- 无完整起止日期的任务只渲染左侧信息，不渲染任务条；
- 用业务日期计算自然日宽度，不通过浏览器时区把日期前移或后移；
- “今天”定位到可视区中央，左右箭头移动一个当前可视窗口；
- 任务条无拖拽、缩放或状态色逻辑。

两个甘特图复用上述基础组件，只替换数据范围和左侧展示字段。

## 8. 版本模块

- 版本列表按服务端创建时间倒序，不在前端二次猜测排序；
- 创建成功后导航到新版本 `/list`；
- 完成版本前请求 `completion-impact`，确认弹窗显示返回的未完成数量；
- 删除版本成功后使用响应的 `next_version_id` 导航，空值进入无版本状态；
- 版本编辑表单加载项目成员，展示部门名称，按后端冲突详情标明不可移除人员；
- 版本任务仍调用任务 API，不建立 `versionTaskApi` 或第二套前端模型。

## 9. 前端测试

新增 Vitest、Vue Test Utils 和 jsdom，最低覆盖：

- 路由鉴权、管理员守卫和返回地址；
- 登录首次注册/后续登录/失败保留部门姓名；
- 任务默认筛选、搜索组合、创建或转交时的成员任务上限错误提示；
- 零任务成员仍显示；
- 表单默认值、日期校验和 500 字限制；
- 409 冲突保留表单并提示刷新；
- 排序成功、失败回滚和冲突重载；
- 无日期甘特任务不绘制条；
- 版本空状态、完成确认、删除后导航；
- 归档项目所有写入口禁用。

关键端到端闭环再使用 Playwright 覆盖：登录 → 创建项目 → 添加成员 → 新建任务 → 创建版本 → 版本排期查看 → 删除版本任务仍保留。

## 10. 设计与开发门禁

- 数据库、后端、鉴权、Vue Router、HTTP 层和测试基础可以先开发；
- 团队任务面板、版本排期和两个甘特图的正式页面必须等待 V3.0 新设计稿冻结；
- 登录/注册双模式、项目成员管理、部门删除和邀请码持续复制也需要进入设计补充清单；
- 设计未冻结前可以制作技术原型，但不得作为最终视觉验收基线。

## 11. 共享部署前端约束

- 前端和后端通过同一个 HTTPS 域名提供服务，避免跨域 Cookie 和 CSRF 配置复杂化；
- 生产构建由共享服务器托管，不使用每位成员各自的本地前端；
- 使用路由级动态导入拆分页面，解决当前单个 JavaScript 包超过 1 MB 的构建警告；
- 首期验证当前 Chrome 和 Edge 主版本，其他浏览器按最佳努力兼容。
