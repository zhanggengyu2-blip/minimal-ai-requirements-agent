# V3.0 开发任务拆分

> 状态：可进入估算与排期
> 原则：先身份和成员，再任务数据，再版本排期，最后完成甘特与整体验收
> 实施进度：T0～T4 已完成；下一任务包为 T5，正式页面需等待新版设计冻结

## 1. 里程碑

| 里程碑 | 可交付结果 | 依赖 |
|---|---|---|
| M0 数据基线 | 空库可用 Alembic 完整创建，首个管理员可初始化 | 无 |
| M1 身份与成员 | 可用邀请码注册、统一密码登录、鉴权并管理部门/邀请码/项目成员 | M0 |
| M2 团队任务 | 可创建、编辑、删除、筛选、排序任务并处理并发冲突 | M1 |
| M3 版本排期 | 可维护多版本、参与人员并复用同一任务数据 | M2 |
| M4 甘特与质量 | 两个只读甘特、自动化测试和交付文档完成 | M2、M3 |

## 2. 任务包

### T0：迁移基础和测试库重建

- 接入 Alembic，建立 `0001_v3_baseline`；
- 移除生产启动时的 `create_all` 和手写字段升级依赖；
- 增加幂等 seed 与首个管理员初始化命令，管理员直接创建且不要求邀请码；
- 配置 SQLite 外键、WAL、busy timeout；
- 建立临时数据库测试夹具；
- 在明确校验目标路径后执行一次测试库清空。

完成标准：全新空目录可一条命令升级到 head；重复升级无副作用；本地服务可由新库启动。

### T1：身份、会话与组织权限

- 新增用户、会话、角色、邀请码摘要和加密存储模型；
- 实现部门＋姓名＋邀请码首次注册；
- 实现部门＋姓名＋公司统一密码日常登录；
- 实现 HttpOnly 会话、CSRF、退出和当前用户；
- 实现 7 天空闲过期、30 天绝对过期和滚动续期；
- 部门模型移除状态，增加永久删除和引用冲突；
- 管理员邀请码列表持续展示并支持复制完整邀请码；
- 所有现有业务路由接入当前用户依赖；
- 补齐身份、权限和敏感信息测试。

完成标准：未登录不能访问业务接口；普通成员不能访问管理员接口；统一密码和会话令牌不进入数据库、日志或前端持久化存储；邀请码只以摘要和加密密文保存。

### T2：项目成员与项目可见性

> 后端状态：已完成。成员管理弹窗属于 T4 前端应用壳范围。

- 新增 `project_member`；
- 创建项目时自动加入创建者；
- 普通成员项目列表按成员关系过滤；
- 管理员可查看全部项目并协助维护成员；
- 增加成员管理接口及弹窗；
- 任意项目成员均可归档或重新打开项目；
- 实现至少一名成员和“仍负责任务不可移除”校验；
- 现有需求、访谈接口增加项目访问控制。

完成标准：通过直接输入 URL 或对象 ID 也不能越权读取、修改其他项目。

### T3：任务后端

> 状态：已完成。`version_id` 的真实版本关系将在依赖的 T6 版本表建立后启用。

- 新增任务、泳道和枚举模型；
- 实现查询、搜索、状态筛选和 1000 条上限；
- 实现创建、详情、更新、永久删除；
- 实现负责人/版本/日期业务校验；
- 实现任务修订号和 409；
- 实现完整泳道排序和泳道修订号；
- 覆盖负责人变化、排序、删除和归档只读测试。

完成标准：任务服务的事务、不变量和并发测试全部通过。

### T4：前端路由、登录和应用壳

> 状态：已完成。任务和版本正式页面仅建立稳定路由与只读上下文，未越过设计门禁提前实现。

- 引入 Vue Router，拆分 `App.vue`；
- 建立登录/首次注册双模式布局、应用布局、鉴权和管理员守卫；
- Axios 接入 Cookie、CSRF、401/403/409 分类处理；
- 改造左侧项目路由与归档项目查看入口；
- 更新部门、邀请码和项目成员页面；
- 增加前端测试运行环境。

完成标准：刷新、后退和书签恢复项目与模块；筛选按产品规则恢复默认。

### T5：团队任务面板

- 实现成员泳道、零任务状态、计数、搜索和筛选；
- 实现共用任务新建/编辑弹窗；
- 实现删除二次确认；
- 实现泳道内拖拽排序及失败回滚；
- 实现截断提示与排序禁用；
- 实现归档只读和并发冲突交互；
- 编写组件与页面测试。

完成标准：对应 PRD 验收 6～17、28～29 可通过。

### T6：版本后端

- 新增版本和参与人员模型；
- 实现版本列表、创建、详情、修改、完成影响和删除；
- 实现参与人员至少一人、必须为项目成员、仍负责任务不可移除；
- 实现任务负责人自动加入版本参与人员；
- 删除版本事务内解除任务关联；
- 实现版本修订号和并发测试。

完成标准：删除版本不删除任务，版本状态切换不改变任务状态。

### T7：版本排期前端

- 实现无版本空状态、版本切换和创建后导航；
- 实现版本创建/编辑弹窗和部门只读展示；
- 实现列表视图、零任务参与人员和上下文新建任务；
- 实现完成版本确认及未完成数量；
- 实现删除版本确认、影响数量和后续导航；
- 实现并发冲突和归档只读；
- 编写页面测试。

完成标准：对应 PRD 验收 1～5、18～24、26～27、30～31 可通过。

### T8：共用甘特图

- 实现日、周、月刻度和日期坐标计算；
- 实现今天居中、左右窗口移动和横向滚动；

- 点击任务名称或任务条打开共用编辑弹窗；

### T9：契约、回归与交付

- 更新共享内网部署、管理员初始化和数据库升级说明；

完成标准：自动化测试通过，手工验收无阻塞项，文档可让新开发者从空库启动系统。

## 3. 推荐开发顺序

```text
T0
→ T1
→ T2
→ T3 与 T4
→ T5
→ T6
→ T7 与 T8
→ T9
```

T3 和 T4 可在接口契约冻结后并行；T7 与 T8 可在任务弹窗及版本 API 稳定后并行。不要在身份、项目成员和数据库基线未完成前直接用假用户开发正式任务权限逻辑。

设计门禁：T0～T4 中不依赖最终视觉的部分可以先开发；T5、T7、T8 的正式页面必须等待新版设计冻结。

## 4. 每个任务包的完成定义

- 代码、迁移、接口 schema 和测试同时提交；
- 新接口已经进入 OpenAPI；
- 失败、权限、空状态、并发冲突和归档只读路径均有验证；
- 不把邀请码、会话令牌或用户真实数据写入日志、测试快照和示例；
- 不依赖未提交的本地数据库或手工状态；
- 与 PRD、页面交互说明和本技术方案不存在已知冲突。

## 5. 上线门槛

- 当前库确认为测试库并按方案完成一次性重建；
- 至少一名管理员可正常登录；
- 普通成员越权、归档项目写入和乐观锁冲突测试通过；
- 项目达到 1000 条任务边界时有明确提示且页面不失去响应；
- 删除任务和版本的确认文案与实际数据效果一致；
- 新版设计稿完成冻结，现有旧 PNG 不作为最终验收依据。

当前不把备份和恢复设为首次上线门槛。上线后需单独规划数据库与附件备份；在此之前的数据丢失风险已接受。
