# V3.0 需求基线与变更规则

> 基线编号：V3.0-R3
> 冻结日期：2026-08-24
> 当前状态：需求已冻结，设计待确认
> 产品范围：团队任务与版本排期

## 1. 基线范围

V3.0-R3 包含：

- 团队任务面板与团队任务甘特图；
- 任务创建、编辑、永久删除、状态、优先级、日期和成员内排序；
- 每位负责人在单个项目中最多拥有 200 条任务的容量边界；
- 多版本创建、切换、编辑、删除和人工状态维护；
- 版本排期列表与版本排期甘特图；
- 任务在团队任务与版本排期之间的一份数据同步；
- 归档项目只读规则及桌面 Web 适配边界。

V3.0-R3 不包含项目知识库。项目知识库计划在 V4.0 中使用独立 PRD、设计和开发计划定义，不得因目录、分支或旧页面结构中的历史命名被误纳入 V3.0。

## 2. 冻结文件

需求基线由以下文件共同组成：

1. `product/v3.0/《团队任务与版本排期需求说明-V3.0》.md`：产品规则和验收标准的唯一主文档；
2. `product/v3.0/《V3.0页面结构脑图》.md`：导航、页面结构与模块边界的辅助文档；
3. `product/v3.0/《V3.0页面与交互说明》.md`：页面行为、状态、校验和高风险操作说明；
4. `product/v3.0/《V3.0需求变更记录》.md`：冻结后的需求变更记录。

`product/v3.0/极简 AI 团队需求管理智能体 V3.0 页面结构.xmind` 保留的是冻结前历史内容，当前不属于 V3.0-R3 基线。若继续使用 XMind，应根据冻结后的 Markdown 脑图另行同步后再纳入基线。

现有 9 张 PNG 是设计修订输入，不是冻结设计。只有根据 V3.0-R3 重新导出的设计稿和完成签署的设计冻结检查表，才能成为开发依据。

## 3. 事实优先级

发生冲突时按以下顺序执行：

1. 已批准且已记录的需求变更；
2. V3.0-R3 冻结 PRD；
3. 冻结后的页面与交互说明及设计稿；
4. 冻结后的 Markdown 页面结构脑图；
5. 其他历史资料、旧 UI 和旧 XMind。

任何人不得依据低优先级资料静默覆盖高优先级规则。发现冲突时应停止相关实现并记录问题。

## 4. 冻结规则

- 冻结后不得直接改变产品范围、字段、状态、权限、数据处理或验收标准；
- 错别字、链接修复和不改变含义的排版调整可直接修改，但需在提交说明中标记；
- 纯视觉微调不得改变入口、字段、交互能力或用户可见业务含义；
- 技术实现细节在不改变用户行为和验收标准时，不构成需求变更；
- 开发中发现需求无法实现、成本显著超预期或存在数据风险时，必须先提交变更评估，不得自行删减。

## 5. 需求变更流程

1. 在需求变更记录中登记变更内容、原因和提出人；
2. 说明影响的 PRD 条目、页面、数据、接口、测试和排期；
3. 给出“进入 V3.0、延期到后续版本、拒绝”三种处理建议；
4. 由产品负责人确认结果；
5. 批准后统一修改相关基线文件，并生成新的基线修订号；
6. 通知设计、开发和测试使用新基线。

未经确认的讨论、聊天记录和设计尝试不自动成为需求。

分支重命名不属于需求冻结本身，应在获得明确授权后单独执行；如果该分支已经发布到远端，还需同步调整远端分支及其他协作者的跟踪关系。

设计 PNG 和 XMind 属于二进制资产，可在设计重新导出后再决定使用普通 Git、Git LFS 或独立设计存储。若后续需要跟踪这些二进制资产，应再次获得明确授权后调整 `.gitignore`。
