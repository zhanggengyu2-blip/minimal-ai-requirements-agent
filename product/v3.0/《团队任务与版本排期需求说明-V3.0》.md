# 团队任务与版本排期需求说明 V3.0

> 文档状态：需求基线已冻结
> 基线版本：V3.0-R2
> 更新日期：2026-08-23
> 冻结日期：2026-08-23
> 所属产品：极简 AI 团队需求管理智能体
> 核心主题：团队任务面板与多版本排期

---

## 0. 一页产品地图

### 0.1 一句话定位

在现有项目和团队成员体系内，提供一套简单、低成本、共同维护的 Todo 与版本排期工具，满足小团队日常任务管理和版本时间展示需求，减少对额外付费项目管理工具的依赖。

### 0.2 核心用户与问题

本功能面向项目内部成员。团队目前已经能够收集、访谈和分析需求，但需求之外的普通工作、成员待办和版本排期仍需依赖飞书、Jira、表格等其他工具维护，产生额外费用和系统切换成本。

本期不追求建立复杂的专业项目管理系统，而是提供团队真正会使用的基础能力：大家在同一个页面维护任务，并可将同一份任务数据切换成甘特图查看；需要进行版本排期时，再按版本查看参与人员及其任务时间。

### 0.3 最小价值闭环

```text
项目成员共同创建任务
→ 指定唯一负责人
→ 在团队任务面板按成员维护待开始、进行中、已完成和已取消任务
→ 可选填写任务时间和所属版本
→ 在任务面板甘特图查看项目全部任务
→ 在版本排期中切换或创建版本
→ 查看当前版本参与人员及其任务甘特图
→ 人工维护任务与版本状态
```

### 0.4 当前范围

- 团队任务面板及对应甘特图视图；
- 多版本创建、切换和状态维护；
- 版本排期列表及对应甘特图视图；
- 同一份任务数据在任务面板与版本排期中同步；
- 团队成员共同查看、编辑和删除项目任务；
- 任务搜索、状态筛选、优先级和成员内排序；
- 日、周、月三种甘特图刻度及时间导航。

本需求基线只覆盖团队任务与版本排期。项目知识库不属于 V3.0，计划在 V4.0 中独立定义、设计和开发。

### 0.5 明确非目标

- 不使用 AI 自动拆解任务、选择负责人、制定排期或调整优先级；
- 不做复杂任务依赖、关键路径、自动排期和人力负载分析；
- 不做工时核算、成员效率评分、ROI、OKR 和奖惩管理；
- 不复制飞书、Jira 的完整项目管理能力；
- 不强制任务关联需求，也不以需求关联作为本期功能前提；
- 不做复杂角色视图和精细任务编辑权限；
- 不通过拖拽改变负责人或任务日期；
- 不用任务条颜色编码状态或优先级。
- 不包含项目知识库；该模块延期至 V4.0。

### 0.6 最大假设

小型团队愿意使用一套功能简单但与现有项目、成员体系整合的内部任务工具，以降低额外协作软件成本。该假设尚需通过实际使用情况验证。

## 1. 业务概述与核心问题

### 1.1 参与者

| 参与者 | 主要诉求 | 在本功能中的行为 |
|---|---|---|
| 项目成员 | 查看团队当前工作并维护任务与版本 | 在共同页面创建、编辑和删除任意项目任务，并管理项目版本 |
| 任务负责人 | 明确自己负责的事项及完成情况 | 维护本人名下任务，但系统不限制其编辑其他成员任务 |
| 版本组织者 | 安排版本周期、参与人员和任务时间 | 创建版本、选择成员、调整版本状态和排期 |

本功能用于内部团队协作，不涉及业务审批、绩效评价或奖惩制度。因此所有项目成员使用同一页面，并可修改项目中的全部任务、创建和维护版本，不区分“管理员视图”和“我的任务视图”。

### 1.2 当前业务过程

团队完成需求收集和分析后，仍需要在其他工具中重新创建工作任务、指定成员并维护版本计划。普通工作与需求任务也可能散落在群聊、表格和个人记录中，管理者难以在一个页面查看每位成员手头的工作。

### 1.3 目标业务过程

团队在项目内共同维护任务。任务面板按照成员组织任务，每个成员泳道内平铺任务卡片，并通过搜索与状态筛选控制展示范围；同一页面可以切换为项目级任务甘特图。版本组织者可以为同一项目创建多个版本，并在每个版本下查看独立的参与人员、任务列表和甘特图。

### 1.4 核心问题

本期要解决的不是“如何自动替团队做排期决策”，而是“如何用更低的工具成本，让团队在一个地方共同记录任务，并清楚查看项目与版本中的人员和时间安排”。

## 2. 产品目标与原则

### 2.1 产品目标

1. 让团队成员在一个共享页面维护项目内的全部任务。
2. 让团队快速查看每位成员处于待开始、进行中、已完成和已取消状态的任务。
3. 使用同一份任务数据提供列表与甘特图两种观察方式。
4. 支持一个项目维护多个独立版本排期。
5. 在不引入复杂项目管理规则的前提下，记录版本周期、参与人员及其任务时间。

### 2.2 产品原则

1. **成员优先**：任务页面以负责人为第一层分组，而不是以任务状态分组。
2. **共同维护**：所有项目成员可查看并修改所有任务，也可创建、编辑、删除版本和修改版本状态，不增加精细权限限制。
3. **一份数据**：任务面板与版本排期使用同一份任务数据，任何位置修改后同步更新。
4. **人工决策**：任务分配、时间安排和状态变化主要由成员人工决定。
5. **允许不完整**：任务可以暂时不关联版本，也可以暂时不填写时间。
6. **日期只做展示**：版本日期用于排期参考，不自动决定版本或任务状态。
7. **少做限制**：允许任务时间超出版本周期，系统继续完整展示。
8. **状态独立**：版本状态和任务状态分别由用户维护，完成版本不批量改变任务状态。

## 3. 产品方案与模块关系

### 3.1 总体结构

本期包含两个模块、四种视图：

| 模块 | 列表视图 | 甘特图视图 | 数据范围 |
|---|---|---|---|
| 模块一：团队任务 | 任务面板 | 任务面板甘特图 | 当前项目全部任务 |
| 模块二：版本排期 | 版本排期列表 | 版本排期甘特图 | 当前选中版本的任务 |

两个甘特图必须明确区分：

- **任务面板甘特图**查看整个项目的任务，包括所有版本任务和未关联版本任务；
- **版本排期甘特图**只查看当前选中版本的参与人员和任务。

### 3.2 项目、版本与任务关系

```text
项目
├── 项目成员
├── 团队任务面板
│   └── 项目全部任务
├── 版本 A
│   └── 版本 A 的任务
├── 版本 B
│   └── 版本 B 的任务
└── 未关联版本的任务
```

关系规则：

- 一个项目可以创建多个版本，每个版本拥有独立排期；
- 一个任务最多属于一个版本，也可以不属于任何版本；
- 版本任务自动同步出现在团队任务面板中；
- 未关联版本的任务只出现在团队任务模块，不出现在某个版本排期中；
- 将任务从一个版本移入另一个版本时，任务不复制，只改变所属版本；
- 各视图编辑的是同一份任务数据，但可以按照最终 UI 展示不同的字段子集。

### 3.3 各视图的展示字段边界

各视图使用同一份任务数据，但按使用场景展示不同字段：

| 视图 | 任务展示字段 |
|---|---|
| 团队任务面板 | 预计完成日期、所属版本、进度、任务描述、优先级 |
| 团队任务甘特图 | 所属版本、优先级、进度 |
| 版本排期列表 | 任务状态、开始日期、预计完成日期 |
| 版本排期甘特图 | 所属版本、优先级、进度 |

其中“进度”展示任务当前状态，不形成第二套状态字段。任意视图打开编辑弹窗后，均可编辑同一份完整任务数据；保存结果立即同步到其他视图。

## 4. 模块一：团队任务

### 4.1 任务面板

任务面板以项目成员为第一层分组，每位成员对应一个纵向泳道。任务卡片在泳道内平铺，不再按状态划分二级区块；状态通过卡片标签和全局筛选体现。

任务面板包括当前项目的全部任务：

- 已关联任意版本的任务；
- 未关联版本的任务；
- 已填写时间的任务；
- 未填写时间的任务。

所有项目成员均显示在面板中，包括当前没有任务或筛选后没有结果的成员。成员标题中的任务数量是当前搜索和状态筛选后的结果数。

团队成员可以通过页面全局入口或任意成员泳道内的入口新增任务，也可以编辑、删除或手动修改任务状态。所有成员看到同一个页面，不提供单独的管理员视图或个人视图。成员标题右侧不提供“…”菜单。

同一项目中，每位负责人最多拥有 200 条任务，按该负责人名下全部状态、全部版本的任务总数计算，搜索和筛选不影响计数。达到上限后，不能再为该成员创建任务，也不能把其他任务转交给该成员；该成员已有任务仍可查看、编辑和排序。删除任务或将任务转交给其他成员后，释放出的名额可以继续使用。其他未达到上限的成员不受影响。

### 4.2 任务基本信息

第一版任务字段如下：

| 字段 | 规则 |
|---|---|
| 任务名称 | 必填 |
| 负责人 | 必填且唯一，只能选择当前项目成员 |
| 任务状态 | 必填，默认“待开始” |
| 优先级 | 必填，默认 P1 |
| 所属版本 | 选填，一个任务最多属于一个版本 |
| 开始日期 | 选填，精确到日 |
| 预计完成日期 | 选填，精确到日 |
| 任务描述 | 选填，最多 500 字 |

一项任务只能有一个负责人。多人共同完成的工作由团队自行决定是否拆分为多项任务，系统不提供多人共同负责能力。

任务状态包括：

- 待开始；
- 进行中；
- 已完成；
- 已取消。

四种状态均由用户手动切换。“未完成”是筛选口径，不是独立状态，仅包含“待开始”和“进行中”。

任务优先级采用四级四象限：

- P0：重要紧急；
- P1：重要不紧急；
- P2：紧急不重要；
- P3：不紧急不重要。

开始日期和预计完成日期可以独立填写。仅两者都填写时绘制甘特条；两者都填写时，预计完成日期不得早于开始日期。任务持续天数按自然日计算并包含首尾日期。任务可以不关联版本，也可以超出所属版本周期。

### 4.3 任务面板甘特图

任务面板可以切换为甘特图视图，继续按照项目成员分组，并展示当前项目的全部任务。

展示规则：

- 已填写开始日期和预计完成日期的任务，在时间轴绘制任务条；
- 只填写一个日期或两个日期都未填写的任务仍显示在甘特图左侧，但时间轴不绘制任务条；
- 未关联版本的任务同样显示在左侧；
- 未填写日期或未关联版本时，不额外显示“未排期”标签；
- 用户后续补充日期后，时间轴立即出现对应任务条；
- 任务时间超出所属版本周期时，超出的部分继续正常展示；
- 所有任务条统一使用蓝色，不通过颜色表达状态或优先级。

### 4.4 搜索、筛选与任务交互

- 团队任务模块默认筛选“未完成”；
- 状态筛选项统一为：全部、未完成、待开始、进行中、已完成、已取消；
- 搜索仅匹配任务名称，并与状态筛选按“同时满足”组合；
- 在任务面板和甘特图之间切换时，保留当前搜索词和状态筛选；
- 上述条件只在当前页面访问过程中保留；刷新页面或重新进入模块后恢复默认筛选；
- 搜索或筛选后仍显示全部项目成员，没有匹配任务的成员显示 0 个任务；成员任务数显示当前筛选结果数；
- 任务卡片只允许在同一负责人泳道内上下拖拽排序，不允许跨泳道拖拽改变负责人；
- 甘特图只读，不允许通过拖拽任务条修改日期；甘特图中不展示非功能性的拖拽图标；
- 点击任务卡片、甘特图中的任务名称或任务条，均打开任务编辑弹窗。

### 4.5 创建、编辑与删除任务

- 页面全局“新建任务”打开表单时不预填负责人；
- 从成员泳道内新增任务时，预填当前成员为负责人；
- 从版本参与人员分组新增任务时，预填当前成员和当前版本；
- 修改任务负责人或所属版本时，只移动同一任务，不创建副本；
- 任务加入版本，或版本内任务改给尚未参与该版本的成员时，系统自动把该负责人加入版本参与人员；
- 所有项目成员均可编辑和删除任意项目任务；
- 删除任务必须二次确认，确认后永久删除且无法恢复；任务从团队任务、所属版本及两个甘特图中同步消失；
- 项目成员仍负责至少一项任务时，不允许将其移出项目，必须先转交其全部任务。

任务排序规则：

- 每个项目中的每位负责人维护一套稳定的任务顺序；
- 新建任务默认放在负责人泳道底部；
- 通过编辑修改负责人后，任务放在新负责人泳道底部；
- 团队任务面板、团队任务甘特图、版本排期列表和版本排期甘特图沿用相同的相对顺序；
- 只有团队任务面板支持拖拽排序，其他视图只读；筛选后的任务保持原相对顺序。

## 5. 模块二：版本排期

### 5.1 多版本管理

一个项目可以创建多个版本。版本排期页面需要支持：

- 切换当前查看版本；
- 创建新版本；
- 查看已完成版本；
- 修改当前版本信息及状态；
- 删除版本。

创建版本时设置：

- 版本名称；
- 版本开始日期；
- 版本结束日期；
- 版本参与人员。

版本名称、开始日期、结束日期和参与人员均为必填。结束日期不得早于开始日期；不同版本的周期允许重叠。版本至少保留一名参与人员。

版本状态包括：

- 未开始；
- 进行中；
- 已完成。

创建版本时默认状态为“未开始”。版本状态由用户手动修改，不根据版本起止日期自动切换；用户点击页面顶部的版本状态徽标进行切换。已完成版本仍可查看，也允许重新改为“未开始”或“进行中”。

版本切换下拉只包含实际版本，不提供“全部版本”选项。全部版本不区分状态，统一按创建时间倒序排列；首次进入版本排期页面时默认显示最新创建的版本，创建新版本成功后自动切换到该版本。

项目没有版本，或用户删除最后一个版本后，页面显示版本空状态和“创建第一个版本”按钮。系统不自动创建默认版本，也不跳转到其他模块。

### 5.2 版本参与人员

版本参与人员从当前项目成员中选择。给尚未参与当前版本的项目成员分配版本任务时，系统自动将该成员加入版本参与人员。

参与人员可以暂时没有任务。版本排期列表和甘特图都按照参与人员分组展示。成员名称下方读取并只读展示其现有部门名称；没有部门名称时不显示，不增加版本专属岗位字段。

参与人员仍负责当前版本任务时，不允许从版本中移除，必须先转交任务或将任务移出该版本。“清空”参与人员遵循同样校验，且版本始终至少保留一名参与人员。

### 5.3 版本排期列表

版本排期列表只展示当前选中版本的数据，包括：

- 版本名称和起止日期；
- 当前版本状态；
- 参与人员；
- 每位参与人员负责的任务；
- 任务状态；
- 已填写的任务开始日期和预计完成日期。

每个参与人员分组都提供“添加任务”入口；零任务时使用空状态入口。任务可以在版本排期列表中创建和修改，保存后自动同步到团队任务面板。

版本排期模块默认状态筛选为“全部”。搜索、筛选项和组合规则与团队任务一致；在版本排期列表和甘特图之间切换时保留当前搜索词和状态筛选。搜索或筛选后仍显示当前版本全部参与人员，没有匹配任务的参与人员显示 0 个任务；参与人员任务数显示当前筛选结果数。刷新页面或重新进入模块后恢复默认筛选。

### 5.4 版本排期甘特图

版本排期列表可以切换为甘特图视图。甘特图左侧按照当前版本参与人员分组，右侧展示任务时间轴。

展示规则：

- 只展示当前选中版本的任务；
- 同时具有开始日期和预计完成日期的任务绘制任务条；
- 只填写一个日期或两个日期都未填写的任务仍显示在左侧，但时间轴不绘制任务条；
- 不显示“未排期”标签；
- 后续补充日期后立即生成任务条；
- 任务时间允许超出版本周期，甘特图继续展示超出部分；
- 版本日期只作为排期参考，不自动改变任务状态；
- 所有任务条统一使用蓝色，不通过颜色表达状态或优先级；
- 甘特图只读，点击任务名称或任务条打开任务编辑弹窗。

两个甘特图均支持日、周、月三种刻度，默认使用周刻度，并支持横向滚动。点击“今天”将当天定位到可视区域中央；左右箭头按当前刻度移动一个可视时间窗口。同一模块切换列表与甘特图时，保留上次选择的甘特图刻度。

### 5.5 版本完成与删除规则

当用户主动将版本状态修改为“已完成”时：

- 系统提示当前版本的未完成任务数量；
- 只修改版本状态，不改变版本内任何任务的状态；
- 版本状态和任务状态允许不一致；
- 重新打开版本、在已完成版本中新建任务或移入任务时，也不自动改变任务状态。

“未开始”和“进行中”之间直接切换。切换为“已完成”时必须二次确认并展示未完成任务数量；将已完成版本重新切换为“未开始”或“进行中”时直接切换并显示成功提示。

删除版本时必须二次确认，并提示受影响任务数量。删除版本不删除任务；原版本下的任务自动变为未关联版本，并继续保留在团队任务面板及任务面板甘特图中。

### 5.6 权限与归档项目

- 所有项目成员均可创建、编辑和删除版本，也可修改版本状态；
- 本期不增加版本创建人或项目管理员专属权限；
- 归档项目仍可查看团队任务和版本排期，但所有创建、编辑、删除、排序和状态修改操作均为只读；
- 归档项目中的搜索、筛选、视图切换和甘特图时间导航仍可使用。

## 7. 验收标准

1. 一个项目可以创建多个版本，并能在版本排期页面切换和创建版本。
2. 每个版本拥有独立的参与人员、任务列表和甘特图。
3. 一个任务最多属于一个版本，也可以不属于任何版本。
4. 版本任务会自动出现在团队任务面板中，两处修改保持同步。
5. 团队任务面板及其甘特图展示当前项目全部任务；版本排期及其甘特图只展示当前版本任务。
6. 两个模块的列表和甘特图都按照成员分组，不以任务状态作为第一层分组；团队任务面板显示全部项目成员。
7. 任务状态统一为待开始、进行中、已完成、已取消，并可由用户手动切换；“未完成”只包含待开始和进行中。
8. 新建任务时，名称、负责人、状态、优先级必填；状态默认待开始，优先级默认 P1；描述最多 500 字。
9. 优先级依次为 P0 重要紧急、P1 重要不紧急、P2 紧急不重要、P3 不紧急不重要。
10. 开始日期和预计完成日期可独立填写；两者齐全时预计完成日期不得早于开始日期，并按包含首尾的自然日绘制任务条。
11. 未形成完整起止日期的任务仍出现在甘特图左侧，时间轴不绘制任务条，也不显示“未排期”标签。
12. 任务时间允许超出版本周期，甘特图完整展示超出部分；所有任务条统一为蓝色。
13. 团队任务默认显示未完成，版本排期默认显示全部；搜索仅匹配任务名称，并与状态筛选同时生效，切换同模块视图时保留条件。
14. 任务卡片只能在同一负责人泳道内上下排序，不能通过拖拽改变负责人；两个甘特图均不支持拖拽修改日期。
15. 点击任务卡片、甘特图任务名称或任务条可以打开任务编辑弹窗。
16. 所有项目成员都可以创建、修改和永久删除全部项目任务；删除后所有相关视图同步移除该任务。
17. 仍负责项目任务的成员不能移出项目；仍负责版本任务的参与人员不能从版本移除，版本至少保留一名参与人员。
18. 版本名称、起止日期和参与人员必填；结束日期不得早于开始日期，不同版本周期可以重叠。
19. 版本状态默认为未开始，且只由用户通过状态徽标手动修改；版本日期不自动决定版本或任务状态。
20. 版本下拉不提供“全部版本”，全部实际版本按创建时间倒序排列，首次进入默认显示最新创建版本。
21. 完成版本只修改版本状态并提示未完成任务数量，不改变任何任务状态；已完成版本可重新打开。
22. 删除版本后任务不丢失，而是转为未关联版本任务；删除确认须提示受影响任务数量。
23. 每个版本参与人员分组都可新增任务；从上下文入口新增时正确预填负责人和版本，修改负责人或版本只移动同一任务。
24. 版本成员展示既有部门名称且只读；无部门名称时不展示，不创建版本专属岗位字段。
25. 两个甘特图均支持日、周、月刻度，默认周；“今天”居中定位当天，左右箭头按当前刻度移动一个可视窗口。
26. 所有项目成员均可创建、编辑、删除版本和修改版本状态，不增加版本创建人或管理员专属权限。
27. 归档项目中的团队任务和版本排期可查看但不可修改，所有写操作和拖拽排序均禁用。
28. 每位负责人在项目内维护一套稳定任务顺序；新建或变更负责人后的任务进入泳道底部，四个视图复用相同相对顺序。
29. 筛选后仍显示全部项目成员或版本参与人员，任务数显示当前结果数；刷新或重新进入模块后恢复默认筛选。
30. 没有任何版本时显示版本空状态和“创建第一个版本”入口，不自动生成默认版本。
31. 版本切换为已完成时二次确认并显示未完成任务数；其他版本状态切换直接完成并给出结果提示。
32. 同一项目中每位负责人最多拥有 200 条任务；达到上限后仅限制为该成员新建或转入任务，已有任务的查看、编辑和排序不受影响，删除或转出任务后恢复可用名额。

## 8. 成功判断、假设与风险

### 8.1 主要成功判断

团队能够在当前系统内持续维护日常任务和版本排期，不再必须依赖另一套付费项目管理工具完成基础 Todo 与甘特图管理。

### 8.2 可观察指标

- 有成员持续创建和更新项目任务；
- 多位项目成员共同维护同一个任务面板；
- 项目实际创建并使用多个版本排期；
- 用户在任务面板和版本排期之间切换查看同一批任务；
- 任务日期为空和超出版本周期时，团队仍能正常完成维护工作。

本期不预设未经验证的使用次数或转化率目标。

### 8.3 主要风险

| 风险 | 影响 | 产品应对 |
|---|---|---|
| 功能过度扩张 | 逐渐变成复杂项目管理系统 | 坚持 Todo、成员分组、多版本和基础甘特图范围 |
| 所有人可编辑导致误操作 | 任务内容或状态可能被他人修改 | 作为内部协作风险接受，暂不增加复杂权限 |
| 任务不填日期 | 甘特图信息不完整 | 保留左侧任务，不制造默认日期或虚假时间条 |
| 版本状态与任务状态不一致 | 用户可能误以为版本完成代表任务全部完成 | 完成版本时提示未完成任务数量，并明确不改变任务状态 |
| 单个成员积累过多任务 | 泳道难以浏览和维护 | 每位负责人在单个项目中最多拥有 200 条任务，达到上限后引导删除或转交任务 |
| 低价替代价值未经验证 | 团队仍可能继续使用原工具 | 通过真实团队持续使用情况验证，不提前扩展复杂能力 |
